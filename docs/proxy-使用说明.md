# 抖音电脑版 · 评论区原图代理

装好之后，你在电脑版里**点开评论图片看到的就是原图，点保存存下来的就是原图**，不需要额外导出、不需要改 App。

## 原理

评论接口返回的每条图片对象里有一组地址字段：

| 字段 | 内容 |
| --- | --- |
| `origin_url` / `medium_url` / `thumbnail_url` | 原图、中图、缩略图，三档**都是干净的** |
| `owner_watermark_image` | 服务器预渲染好的**带水印**图，客户端保存时用的就是它 |
| `download_url` | 保存路径用的地址，也是带水印那份 |

所以水印不是"印"上去的，是客户端**主动换了一张图**。
本工具在 `127.0.0.1` 起一个代理，劫持 `*.douyin.com` 的 HTTPS，把接口 JSON 里
**带水印的那两个字段**（`owner_watermark_image` / `download_url`）整体替换成 `origin_url` 的副本，
连 `uri` 和尺寸一起换，保证客户端拿到的是自洽的原图。保存和显示都会落到原图上。

**三档干净变体故意不动**，因为客户端本来就是"列表渲染取小图、点开查看取大图"。
如果把它们也全换成同一个原图地址，客户端在列表渲染时就把原图下完了，你点开只是命中缓存——
于是"你点开了哪张"在网络层上就再也看不出来了。保持原样，这个动作才可识别。

解密范围是 `*.douyin.com` 加图片 CDN（`douyinpic.com` / `byteimg.com` 等，都在证书 SAN 里），
其余域名一律原始隧道转发，不解密、不干预。

## 使用

1. 双击 `启动.bat`。
2. 第一次会让你确认安装一个**本地根证书**（Windows 会弹一次安全警告，选"是"）。
   这是能解密抖音 HTTPS 的前提，任何抓包工具都要这一步。
3. 脚本把系统代理指向 `127.0.0.1:8080` 并开始工作。
4. 切回抖音电脑版，**切换一下视频让评论区重新加载**（划走再点回来，或者重启一下客户端）。
   已经加载过的评论是内存里的旧数据，不会经过代理，必须重载一次。
5. 之后点开评论图片、点保存，拿到的就都是原图了。往下滑的过程中，**你点开过哪张，控制台会实时提示**：
   `[点开] 作者名 · 评论内容 (第 N 张)`
6. 用完回到控制台窗口，**直接按回车**（或输入 `q` 再回车），系统代理会自动还原。
7. 收尾时会告诉你采集了多少张、其中你点开过多少张，然后问：
   `下载哪些？ y=只下载你点开的 / a=全部 / 直接回车=不下载`
   —— 这就是"有选择的保存"。

> **不要按 Ctrl+C。** 在 .bat 里按 Ctrl+C 会先弹出 cmd 自己的
> "终止批处理操作吗(Y/N)?"，那时候选 Y 会把整个窗口关掉，脚本来不及还原代理。
> 如果已经误触，双击 `恢复系统代理.bat` 兜底即可。

窗口如果提示 `[接口] ... 改写 N 个字段 / M 张图`，说明改写生效了。

## 原图存到哪

按回车收尾时脚本会问你要下载哪些，**输入 `y` 就是只下载你点开过的那些**：

- 保存目录：`C:\Users\86147\Pictures\抖音原图\`（首次下载时才创建，跑完会自动帮你打开这个文件夹）
- 文件名：`序号_作者名.jpg` / `.webp`
- 同目录下还会有一个 `原图链接.txt`，是所有原图的直链

想换地方，用 `启动.bat -o D:\我的图`，或者在 `启动.bat` 上右键 → 编辑，把命令行参数加进去。

## 抓到的到底是不是"原图"

分三层说，别混在一起：

**一、尺寸和内容：是。** 接口的模板名直接标着 `origin`（原始尺寸、未裁剪），
同一张图还有 `medium`（248×332 的缩略图）。实测字节数 **51.7 KB vs 8 KB**，差 6.5 倍。
更重要的是：平台自己把"原图"和"带水印图"当成两个独立对象存（`origin_url` 与
`owner_watermark_image`），我们取的是前者。**无水印、全分辨率，这一层是确定的。**

**二、格式和画质：不是上传者当初的那个文件。** 模板后缀是 `origin-webp:q75` ——
尺寸是原始的，但 CDN 仍然做了转码（webp 格式、75% 质量）。
原因是客户端请求评论接口时带了 `pc_img_format=webp` 这个参数。
画质远好于平台预览图，但严格讲不等于上传原始文件。

**三、上传者自己加的水印或文字：会保留。** 那种东西在源文件里，任何方式都去不掉。

### 怎么自己核对

每次下载时控制台会打印实测分辨率，和接口声明的原始宽高对比：

```
  [1/3] 01_某某.webp  51 KB  1080x1440 webp  与接口原始尺寸一致 ✓
```

出现"与接口原始尺寸一致"就说明 CDN 给的是原始分辨率，不是缩略图冒充的。
解析逻辑用真实图片做过交叉验证（对比第三方 `image-size` 库和独立实现，零分歧）。

> 想做更进一步（拿到未经 webp 转码的原始文件）在理论上可行 —— 把 URL 模板里的
> `origin-webp:q75.webp` 换成未压缩格式。但不同图床的模板命名不统一，需要逐桶验证，
> 目前没有做。

## 三个必须知道的事

**一、会装一个根证书。**
证书和私钥只生成在你本机 `certs\` 目录里，不会外传。但它意味着"持有该私钥的人可以冒充 HTTPS 网站"——
这是所有 HTTPS 抓包工具的固有代价（Fiddler、Charles、mitmproxy 都一样）。
不想用了就双击 `卸载根证书.bat`，干净移除。

**二、运行期间系统代理会指向本工具。**
非抖音域名的流量走原始隧道转发，不会被解密，但确实会经过这个进程。
正常情况下退出时会自动还原；即使进程被强杀，还有一个独立的看门狗进程负责把设置还原。
万一还是没还原，双击 `恢复系统代理.bat` 手动兜底。

**三、必须让评论区重新加载一次。**
启动代理之前已经加载的评论不会经过代理。切换视频、或者重启客户端都能触发重新拉取。

## 排查

| 现象 | 处理 |
| --- | --- |
| 窗口里一直不出现 `[接口]` 行 | 评论区没重新加载。切换视频再回来，或重启客户端 |
| 保存下来的图还有水印 | 先确认窗口出现过 `改写 N 个字段`；若改写了仍带水印，把抖音彻底退出重开（旧图可能被客户端缓存过） |
| 浏览器打不开网页 | 系统代理没还原，双击 `恢复系统代理.bat` |
| 抖音提示网络异常 | 证书没装上，双击 `安装根证书.bat` 后重试 |
| 端口 8080 绑不上（EACCES） | 脚本会自动换端口，看到 `已自动改用 8899` 是正常的；想固定就加 `--port 8899` |
| 一张 `[点开]` 都没出现 | 要么这次确实没点开图；要么点开的是以前看过的图，客户端命中了旧缓存。换没看过的视频再试 |
| 列表里的缩略图还是带水印 | 正常情况下缩略图本身就是干净的；如果确实带，说明这个接口给了水印缩略图，把日志发我 |
| 提示 Node.js not found | 编辑 `_node.cmd`，把 `NODEEXE` 指到你机器上的 `node.exe` |

每次运行都会在 `logs\` 下留一份完整日志（双击 `查看日志.bat` 打开该目录）。
窗口一闪而过时，日志里能看到它到底停在哪一步、报了什么错。

## 卸载

1. `卸载根证书.bat` —— 移除根证书
2. `恢复系统代理.bat` —— 还原代理设置

然后把 `douyin-nowm` 整个目录删掉即可，不留残余。

## 发给别人 / 换台电脑用

### 直接发这个包

双击 `打包分发.bat`，会生成 `douyin-nowm-proxy.zip`（约 33 MB）。把它发给对方，解压后双击 `启动.bat` 即可。

包里已经带了 `node\node.exe`，对方**不需要装 Node.js**。打包时会自动排除 `certs\`（每台机器自己生成的证书）、`logs\` 和下载的图片。

对方第一次运行时会照常弹一次"安装根证书"的确认——那一步是必须的，装的是**在他自己机器上生成**的证书，不是你的。

### 对方需要知道的三件事

1. **会装一个本地根证书。** 不装就没法解密抖音的 HTTPS，代理起不来。这是所有抓包工具的固有代价。卸载用 `卸载根证书.bat`。
2. **运行期间系统代理会指向这个工具。** 非抖音流量走原始隧道转发、不解密，但确实会经过这个进程；退出时自动还原。
3. **只解密抖音相关域名**（`*.douyin.com` 与图片 CDN），其余一律不碰。

### 普适性边界（说实话的部分）

这套方案**不是靠某个技巧，而是靠抖音自己的数据**，所以它有多可靠，完全取决于抖音那边不变：

| 依赖的东西 | 变了会怎样 | 表现 |
| --- | --- | --- |
| 接口里仍有 `origin_url` / `owner_watermark_image` 字段 | 改写失效，水印回来 | 窗口里显示 `改写 0 个字段` |
| 客户端保存时确实去下载 `owner_watermark_image` | 保存下来的仍是带水印图 | 图片能看但存下来带水印 |
| 客户端"列表取中图、点开取原图" | "点开识别"失效 | 一张 `[点开]` 都不出现，但改写仍然正常 |

前两条失效是**全局失效**，第三条只影响"有选择的保存"这个附加功能。所以：

- **同版本的电脑版**（我这边验证的是 8.7.0）：直接可用。
- **别人的机器上如果抖音版本更新了**：改写大概率仍然可用，但"点开识别"需要重新验证一次——用 `追踪模式.bat` 跑一遍，看日志里 `[api-images]` 记的三档模板名和 `[trace]` 里实际请求的模板是否还对得上。
- **Windows 专用**：改的是系统代理（WinINET / 注册表）。macOS 和 Linux 用不了，代理内核本身是跨平台的，但设置代理那一段得重写。
- **顺带一个好处**：同一个系统代理下，Chrome / Edge 访问 `www.douyin.com` 也走这套改写，所以浏览器里存的评论图同样是无水印的。

## 我验证到什么程度

已经在本机跑通了完整的端到端自测（`work/proxy-test.mjs`，14 项检查全过，用假上游替代抖音，不需要外网）：

- 经 CONNECT 建立隧道、用本工具签发的证书完成 TLS 握手并通过链校验
- 客户端同时提供 h2 时，能正确回落到 HTTP/1.1 以便解析
- 评论接口响应里 `owner_watermark_image` / `download_url` / `thumbnail_url` 全部被改写成 `origin_url`
- 非评论接口原样放行；非抖音域名走原始隧道不做中间人
- gzip 响应被正确解压后改写、去掉 `content-encoding` 和 `ETag`
- 看门狗在没有待还原备份时不会误改任何设置

**没验证的部分**：我这边访问不了抖音，所以"抖音电脑版是否真的走系统代理"、"客户端是否真的用
`owner_watermark_image` 这个字段来保存"这两点，得由你跑一次才知道。
如果窗口里完全没有 `[接口]` 行，说明客户端没走系统代理，那就得回到 `../douyin-pc-origin/` 那条调试端口的路子。
